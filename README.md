# 미리내 MIRINAE — 은하 탐사기

낱말 하나를 씨앗으로 은하 하나를 통째로 만들고, 브라우저에서 **은하 → 항성계 → 행성 표면**까지 끊김 없이 확대해 들어가는 탐사기입니다. 같은 낱말을 넣으면 누구의 브라우저에서든 같은 은하가 만들어집니다.

## 무엇이 들어 있나

| 단계 | 내용 |
| --- | --- |
| 은하 | 별 160,000개(하나하나가 고를 수 있는 항성계), 나선팔·팽대부·성단·성운·먼지띠. 열면 뒤에서 은하 전체를 훑어 행성·생명·문명 신호를 세고, 문명 신호가 잡힌 별을 지도에 표시합니다. |
| 항성계 | 분광형(O~M)에 맞는 온도·질량·밝기·나이, 천간(갑·을·병…) 순서로 이름 붙은 행성들, 거주 가능 구역(초록 띠), 고리. 하늘에는 **그 별의 자리에서 본 은하**가 실제 별 배치 그대로 보입니다. |
| 행성 | 셰이더로 그린 지형·바다·빙하·구름·대기, 가스 거인의 띠와 폭풍, 용암 행성의 갈라진 틈, 문명 행성 밤 쪽의 도시 불빛, 위성. |

### 2단계에서 더한 것

| 기능 | 내용 |
| --- | --- |
| 워프(항성 사이 직접 비행) | 항성계 패널의 '가까운 별'에서 고른 별로 은하 화면을 거치지 않고 날아갑니다. 목적지 쪽으로 돌아본 뒤, 실제 별 배치를 '지금 위치'에서 본 하늘로 그리면서 그 위치를 출발 별에서 도착 별로 옮깁니다. 가까운 별은 시차로 스쳐 가며 빛줄기를 남기고, 남은 거리를 계기판에 보여 줍니다. |
| 탐사 일지 | 들어간 항성계·행성을 저절로 기록합니다. 처음 찾은 곳은 '새 발견', 생명·문명이 있으면 '생명 발견'·'문명 접촉'으로 알려 줍니다. 즐겨찾기·메모·거르기, '다시 가기'로 그 좌표(다른 은하 포함)로 곧장 이동하고, 은하 지도에는 다녀간 별이 금색 점으로 남습니다. 기록은 이 브라우저(localStorage)에만 저장됩니다. |
| 우주 배경음 | 음원 파일 없이 Web Audio로 그 자리에서 만드는 앰비언트입니다. 별 온도가 높을수록 근음이 높고 소리가 밝습니다(뜨거운 별은 장3도, 차가운 별은 단3도). 행성마다 질감이 다르고(가스 거인 울림, 바다 파도, 사막 바람, 얼음 반짝임, 용암 탁탁 소리), 문명이 있으면 별마다 다른 신호음이 되풀이됩니다. 워프·별 고르기·발견 때 효과음이 납니다. **기본은 꺼짐**이며 '배경음' 단추를 눌러야 소리가 납니다. |

### 3단계에서 더한 것

| 기능 | 내용 |
| --- | --- |
| 사진 모드 | HUD를 숨기고 노출·빛번짐·채도·대비·비네팅·필름 입자를 조절합니다. 색감 프리셋(기본·흑백 필름·청사진·황혼·네온), 시간 멈춤, 이름표·궤도선 끄기, 화면비(화면 그대로·16:9·1:1·4:5·9:16, 자르기 안내 표시), 테두리(없음·엽서·관측 기록)를 고른 뒤 PNG로 저장합니다. 색보정은 후처리 셰이더 패스이고, 저장은 그린 직후의 WebGL 화면을 2D 캔버스로 옮겨 자르고 글씨를 얹습니다. |
| 쌍성계 | 별의 약 14%가 쌍성입니다. 동반성은 주성과 같거나 더 차갑고, 두 별은 무게중심을 돕니다. 행성은 두 별 사이 거리의 3.2배 밖에서 둘을 함께 돌고(쌍성 주위 궤도), 거주 가능 구역은 두 별의 밝기를 합쳐 잡습니다. 행성 표면·구름·대기·고리가 해 두 개의 빛을 받고, 행성 하늘에 해가 둘 뜹니다. |
| 블랙홀 | 0번 별은 언제나 은하 한가운데의 초대질량 블랙홀('〇〇의 심장')이고, 별 2,500개에 하나꼴로 항성 블랙홀이 있습니다. 화면의 픽셀마다 광선을 쏘아 중력에 휘게 적분해서, 그림자·광자 고리, 원반 뒤쪽이 위아래로 휘어 넘어오는 모습, 다가오는 쪽이 밝은 도플러 효과, 그 자리에서 본 은하 하늘의 중력렌즈 왜곡을 그립니다. 하늘은 큐브맵에 한 번 그려 둡니다. |
| 행성 저공비행 | 땅이 있는 행성(가스 행성 제외)에서 지금 보던 지점 아래로 내려가 표면 위를 납니다. 카메라를 따라다니는 격자를 셰이더가 궤도 화면과 같은 노이즈 높이만큼 들어 올리므로, 궤도에서 본 대륙·산맥이 그대로 발밑에 있습니다. 카메라는 CPU에서 같은 높이 함수로 앞쪽 지면까지 읽어 산을 미리 넘습니다. 대기 하늘·안개·구름 층·잔물결이 있고, 쌍성계 행성에서는 하늘에 해가 둘 떠서 지형·구름이 두 빛을 받습니다. ← → ↑ ↓ 와 끌기로 조종하거나 자동 비행에 맡깁니다. |

### 배포 전 다듬기

- **지평선의 흰 띠:** 같은 시점에서 줄별 밝기를 재 보니 두 원인이 겹쳐 있었습니다. 하나는 지평선 위를 비스듬히 지나는 구름 층(띠를 최대 +40 밝힘)이었고, 다른 하나는 지형 끝자락의 안개 색이 바로 위 하늘보다 밝았던 것입니다. 하늘 돔이 수평 아래를 어둡게 하는데, 높이 떠 있으면 실제 지평선이 수평보다 아래로 내려가 그 어두운 부분이 드러났습니다. 구름에도 거리 안개를 걸고, 안개 색을 하늘의 지평선 색과 같은 식으로 맞추고, 가까운 곳은 맑고 먼 곳만 짙은 제곱 지수 안개로 바꿨습니다(구름 영향 +40 → +2).
- **하늘이 앞의 물체 위에 덧칠되던 버그:** 하늘 별과 대기 돔이 깊이 검사 없이 투명 물체로 나중에 그려져, 행성과 지형 위에 별빛과 하늘색이 더해지고 있었습니다. 둘을 가장 먼 깊이에 두고 깊이 검사를 켜서 고쳤고, 저공비행 지형이 뿌옇던 것도 함께 사라졌습니다. 대기가 짙은 낮 하늘에서는 별을 흐리게 합니다.

- 별 이름은 한글 음절 생성기와 순우리말 낱말로 만들고, 은하 구역은 동아시아 별자리 구획 **28수**(각·항·저·방…)로 나눕니다.
- 지금 보는 곳(은하·별·행성)이 주소에 담겨, 링크를 보내면 상대도 같은 자리에서 시작합니다.
- 별 이름 검색, 아무 별로 가 보기, 다른 낱말로 새 은하 만들기.

## 접근성에서 챙긴 것

- 3D 화면에서 할 수 있는 일(별·행성 고르기, 들어가기, 뒤로)은 모두 오른쪽 패널의 버튼으로도 할 수 있습니다.
- 고른 대상과 화면 단계가 바뀌면 `aria-live`로 알리고, 단계가 바뀌면 초점을 새 제목으로 옮깁니다.
- `prefers-reduced-motion`이면 카메라 비행·궤도 운동을 줄이거나 끄고, 워프는 화면 전환만 합니다.
- 소리는 자동으로 나지 않습니다. 켜고 끄는 단추(`aria-pressed`)와 음량 슬라이더가 늘 머리말에 있습니다.
- 사진 모드에서는 Esc로 끝내고 초점이 '사진 모드' 단추로 돌아갑니다. 구도를 잡다가 실수로 선택이 바뀌지 않도록 화면 클릭을 받지 않습니다.
- 저공비행은 키보드(← → 방향, ↑ ↓ 높이)만으로 조종할 수 있고, 시작·끝을 `aria-live`로 알립니다.
- 탐사 일지는 네이티브 `<dialog>` 모달이라 초점이 창 안에 머물고 Esc로 닫힙니다. 워프 시작·도착은 `aria-live`로 알리고, 계속 바뀌는 남은 거리 숫자는 스크린리더에 숨깁니다.
- 좁은 화면에서는 패널이 아래 시트가 되고, 시트에 가린 만큼 우주의 중심을 위로 올립니다.

### 점검 결과 (axe 4.14, 2026-10-22)

- 은하 개요·별 선택·항성계·행성·저공비행·블랙홀·탐사 일지·사진 모드, 그리고 375px 모바일(은하·블랙홀)에서 WCAG 2.2 AA와 best-practice 규칙을 돌려 **위반 0건**입니다. 모바일에서는 24px보다 작은 터치 대상과 가로 넘침도 없었습니다.
- axe는 WebGL 캔버스 뒤 배경을 알 수 없어 색 대비를 판정하지 못하거나 문서 배경(검정)만 보고 통과시킵니다. 그래서 화면에 보이는 모든 글자에 대해, 글자 뒤의 반투명 배경 층을 찾아 우주 화면이 흰색·밝은 하늘색·검정일 때로 합성해 대비를 따로 계산했습니다.
  - 처음에는 우주 화면 위에 바로 놓인 9곳(로고, 위치 표시, 아랫줄 안내와 단추)이 밝은 배경에서 1.1~2.3에 그쳤습니다(필요한 값 4.5, 큰 글자 3).
  - 머리말·안내줄·도구 단추에 어두운 유리 배경(불투명도 0.82)을 깔고 패널을 0.86으로 올린 뒤, 뒤가 흰색인 최악 조건에서도 모든 글자가 기준의 1.15배 이상입니다.
- 탐사 일지의 즐겨찾기 단추는 화면에 ★만 보이고 이름은 '○○ 즐겨찾기'여서 보이는 레이블과 접근 이름이 어긋났습니다. 별 기호를 스크린리더에서 숨기고 이름을 글자로 주어 맞췄습니다.
- 화면 단계가 바뀔 때와 사진 모드를 끝낼 때의 초점 이동이 `requestAnimationFrame`에 기대고 있어, 탭이 뒤로 가 화면 갱신이 멈추면 초점이 옮겨지지 않았습니다. 화면 갱신과 상관없이 옮기도록 바꿨습니다.
- 스크린리더 실사용(NVDA 등)은 아직 하지 않았습니다.

## 기술

- React 19 + TypeScript + Vite, three.js(WebGL2), 후처리 블룸
- 결정론적 생성: 32비트 해시 + mulberry32. 별의 위치·분광형은 은하 시드에서, 항성계는 `hash(은하 시드, 별 번호)`에서 나옵니다.
- 셰이더: 3D 심플렉스 노이즈(Ashima Arts, MIT) fbm·도메인 워프·리지 노이즈, 화면 미분으로 법선을 비트는 범프 조명
- 성능: 별 고르기는 three의 Points 레이캐스트 대신 배열을 직접 훑음(16만 개 한 번에 중앙값 1.6ms, 개발 PC 측정). 은하 전체 탐색은 7ms씩 끊어 렌더링을 막지 않음. 행성 셰이더는 은하를 보는 동안 `compileAsync`로 미리 컴파일(첫 항성계 프레임 2.4초 → 74ms, 개발 PC 측정).

- 이웃 별 찾기: 별을 1,200광년 칸의 격자에 담아 가까운 칸부터 넓혀 가며 찾음(전수 검색과 결과가 같은지 테스트).
- 블랙홀: 슈바르츠실트 반지름을 1로 둔 단위에서, 광자 경로를 측지선의 뉴턴식 근사(a = −1.5·h²·x/r⁵)로 픽셀마다 최대 320걸음 적분합니다. 원반은 두께 없는 평면이고 시간 지연·편광 등은 다루지 않는 시각화용 근사입니다. 픽셀 비율을 1.25로 묶어 개발 PC에서 프레임당 약 16ms.
- 저공비행 높이: 셰이더의 3D 심플렉스 노이즈를 JavaScript로 옮겼습니다. 처음에는 GPU와 크게 어긋났는데, 기울기 격자 49칸 가운데 7칸에서 값이 수학적으로 정확히 0이 되고 그 반올림 부호가 32비트(GPU)와 64비트(JS)에서 달라 기울기 방향이 뒤집혔기 때문이었습니다. `Math.fround`로 GPU의 32비트 곱셈·덧셈을 흉내 내 4종 행성 4,096곳에서 최대 오차 0.00006으로 맞췄고, GPU에서 읽은 기준값을 테스트로 고정했습니다.
- 지형 높낮이는 알아보기 쉽게 실제보다 약 10배 과장했고, 비행 계기의 높이는 그 비율을 되돌려 보여 줍니다.

```
src/
  gen/      은하·항성계·행성·이름 생성, 이웃 별 격자 (DOM·three 없이 테스트 가능)
  engine/   three.js 엔진: 화면 6종(은하·항성계·행성·워프·블랙홀·저공비행), 셰이더, 카메라 전환, 사진 모드
  audio/    Web Audio 배경음
  ui/       React HUD: 패널, 탐사 일지, 주소 동기화, 안내
```

## 실행

```bash
npm install
npm run dev
npm test
```

OneDrive 폴더 안에서 `vite build`가 글꼴 파일을 많이 쓰다 멈춘 적이 있어(다른 프로젝트 경험), 빌드는 OneDrive 밖 `--outDir`로 하는 것을 권합니다.

## 만든 방식

1~3단계와 배포 전 다듬기의 코드는 Claude Code(AI)가 작성했습니다. 사람이 정한 방향과 검수한 부분은 진행하면서 이 절에 적습니다.
